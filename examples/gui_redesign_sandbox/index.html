01 — Diagnosis

現状診断:アイディア S級、伝え方 C級

リポジトリのREADME・GUIマニュアル・スクリーンショットを分析した結果、「中身は良いのに伝わらない」典型パターンが見つかりました。

強み(変えない)

  • 唯一無二の課題設定 — 「結合セル・別紙参照・"同上" だらけの dirty Excel」を真正面から扱うOSSは世界でもほぼ存在しない
  • 誠実な設計思想 — 「LLMの主張だけで must_review にしない」verifier の安全側設計は、エンタープライズで信頼される最大の差別化要素
  • ローカル完結 & 承認制の外部送信 — 秘匿性の高いSIer案件にそのまま持ち込める
  • Obsidian 連携・golden test など、細部の作り込みが既に丁寧

スターを阻む5つのボトルネック

  • #1READMEが「説明書」で「デモ」がない — 最初の1スクロールにGIF・Before/Afterがなく、価値の証明まで遠い
  • #2体験までの距離が長い — clone → pip install → LLM設定が必要。スターの大半は「インストール前」に決まる
  • #3GUIの情報設計が弱い — グラフのラベル衝突・evidence の埋没・優先度の視覚的弱さで「すごさ」が伝わらない
  • #4日本語のみで市場が1/20 — "dirty Excel spec" は海外SI・金融・製造でも刺さるのに英語導線ゼロ
  • #5ストーリーの主語がツール — 「機能一覧」ではなく「あの地獄の影響調査が変わる」という読者の物語になっていない

02 — GUI / UX Redesign

GUIリデザイン:「レビューの作業台」として再設計

現GUIの最大の問題は「機能が画面に並んでいるだけ」で、ユーザーの仕事(=影響候補を根拠付きで潰していく)に沿っていないこと。 実際に動くプロトタイプを作りました。そのまま実装の設計図として使えます。

localhost:8765 — SpecImpact Console (Redesign Prototype) フルスクリーンで開く

影響レビューを主役に

機能別メニューではなく must / should / may のトリアージボードを中心に。1候補=1カードで「根拠 → graph path → 必要アクション → 判断ボタン」が完結。Jiraのバックログを消化する感覚でレビューできます。

Evidence を常に1クリック以内に

SpecImpactの魂は「引用元セルまで遡れる」こと。ファイル名+セル範囲+引用文をカード内に直接埋め込み、グラフでもエッジ選択で即表示。「LLMの判定」は作業仮説として明確に分離表示します。

グラフは「読める」密度に

力学レイアウト+衝突回避+ラベルの白フチでラベル衝突を解消。「影響パスを強調」ボタンで変更要求に関係するサブグラフだけを浮かび上がらせ、relation の confirm/reject をその場で実行できます。

「次にやること」ガイド

ダッシュボードを統計の羅列からステップ式の導線に変更。「取り込み済み → 分析済み → must_review 4件が未レビュー」と、いま何をすべきかが常に明確。未処理件数はナビにバッジ表示。

プライバシーを常時可視化

「127.0.0.1 ONLY」「外部送信は承認制」はSpecImpact最大のセールスポイント。設定の奥ではなくサイドバー常設の Privacy Doctor カードとトップバーのチップで常に見せます。

統一デザイントークン

must=赤 / should=橙 / may=青、confirmed=緑 / unconfirmed=橙 / rejected=灰 のセマンティックカラーを全画面で統一。Inter + Noto Sans JP + JetBrains Mono の3書体で「コード/ID」と「説明文」を視覚的に分離。

03 — Growth Strategy

広報戦略:スターは「共感 → 体験 → 拡散」で生まれる

機能を宣伝するのではなく、「Excel設計書の影響調査で消耗した経験」への共感から入る。要点は4つです(詳細は90日プレイブックへ)。

柱1

README を「30秒の映画予告編」に

  • 冒頭に 15秒GIF:dirty Excel → 影響候補カード → セル引用、の流れだけ見せる
  • 1行キャッチ:「その仕様変更、どこに波及する?」をExcel設計書のまま答えるツール
  • Before/After 表:「3日かかる目視grep」vs「evidence付き候補リスト」
  • 英語README(README.en.md)を同時整備し、トップにバッジで言語切替
柱2

「インストール不要」の体験デモ

  • 分析済みサンプル結果を静的サイト化した ライブデモ(本プロトタイプがその雛形)をGitHub Pagesで公開
  • pipx run specimpact demo で合成サンプル一発体験(LLM不要の --no-llm 経路)
  • PyPI 公開 + GitHub Codespaces バッジで「3分以内に動く」を保証
柱3

「あるある」起点のコンテンツ発信

  • Qiita/Zenn:「結合セルと"同上"だらけのExcel設計書をLLMに読ませて影響調査を自動化した話」— 技術記事ではなく体験記として
  • X/Twitter:dirty Excel のスクショ + 解析結果のビフォーアフターを1枚画像で
  • 発表枠:JJUG・DevelopersIO・社内SE系LT、JAWS等の「レガシー改善」文脈
  • Obsidianコミュニティへの逆輸入(Canvas出力はObsidianユーザーに刺さる)
柱4

英語圏 & コミュニティ受け入れ態勢

  • Hacker News「Show HN: Impact analysis for messy Excel specs (common in Japanese SI)」— "日本のSI文化" 自体が良いフックになる
  • r/dataengineering, r/ExperiencedDevs, awesome-llm / awesome-graphrag リストへのPR
  • good first issue を10本用意(ローダー追加・出力フォーマット等の独立タスク)
  • リリースノートを「物語形式」で書き、X とGitHub Releaseで毎回発信
週次タスクまで落とした90日プレイブックを見る

04 — Implementation

実装改善:スターに直結する順に

「正しさ」より「最初の5分の体験」に投資します。優先度順のバックログです。

P0

`specimpact demo` コマンド + PyPI 公開

合成サンプルの ingest → analyze → GUI 起動までを1コマンドで。LLM 設定不要(--no-llm 経路)で確実に動く。「pip install specimpact && specimpact demo」がREADMEの最初のコードブロックになる。

体験距離の短縮
P0

GUIをこのプロトタイプの設計に刷新

影響レビューボード(カード型・優先度色・evidence埋め込み)/ 読めるグラフ(衝突回避・影響パス強調)/ ステップ式ダッシュボード。スクリーンショット映えがそのまま広報資産になる。

「すごい」の瞬間を作る
P1

HTML静的レポート出力(`specimpact report --format html`)

影響レビュー結果を単一HTMLで出力 → そのまま上司・顧客に共有できる。共有されたHTML自体がフッターの「Generated by SpecImpact」リンク経由で新規ユーザーを連れてくる、最強の自己増殖チャネル。

バイラルループ
P1

英語化(README.en / GUI i18n / サンプルの英語版)

"messy Excel specs" は海外でも普遍的な課題。GUI文言は辞書ファイル方式で日英切替を実装し、英語の合成サンプル(注文管理システム等)を1セット追加する。

市場を20倍に
P2

CI バッジ・GitHub Actions・Codespaces 対応

pytest / ruff / release-check を Actions 化してバッジ表示。devcontainer.json を追加し「Open in Codespaces」でブラウザだけで試せるように。信頼感の演出はスターの転換率を上げる。

信頼の可視化
P2

MCP サーバー化 / エディタ連携

影響分析を MCP tool として公開すれば、Claude Code / Cursor などから「この変更の影響は?」と聞ける。いまもっとも拡散力のある「AIエージェント連携」文脈に乗れる。

トレンド接続

まずは新しいGUIを触ってみてください

「利用限度額を999万円→9999万円に変更する」という合成シナリオで、画面 → チェック仕様 → API → DB → 外部IF → テストまで影響が波及する様子を、evidence 付きでレビューできます。
