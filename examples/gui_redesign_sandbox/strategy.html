付録A:README 冒頭テンプレート(コピペ用)

現READMEは2段落目まで読まないと価値がわかりません。以下の構造に差し替えることを推奨します。

# SpecImpact

**「その仕様変更、どこに波及する?」を、汚いExcel設計書のまま答えるツール。**

![demo](docs/images/demo.gif)

結合セル、複数表の混在、「同上」、別紙参照 ——
SIer の Excel 設計書はそのままでは検索もトレースもできません。
SpecImpact は設計書を **evidence 付きの知識グラフ** に変換し、
変更要求を入れると影響候補を `must_review / should_review / may_review` で返します。

|                | これまで                     | SpecImpact                       |
| -------------- | ---------------------------- | -------------------------------- |
| 影響調査       | 目視 + Ctrl+F で数日         | 候補リスト生成は数分             |
| 根拠           | 「たぶんこの辺」             | ファイル・シート・セル範囲を引用 |
| 表記揺れ       | 人の記憶頼み                 | 限度額 ≒ creditLimit を候補化    |
| LLM の扱い     | 出力をそのまま信じる         | verifier が evidence を要求      |

## ⚡ 30秒で試す(LLM不要)

```bash
pip install specimpact
specimpact demo        # 合成サンプルで ingest → analyze → GUI 起動
```

> 🔒 すべてローカルで動作。外部送信は明示的な承認制です。

Show HN ドラフト(英語)

Show HN: Impact analysis for messy Excel specs – merged cells, "ditto", and all

In Japanese enterprise IT, system specs live in Excel: merged cells, "same as above", references to other sheets. When a requirement changes, engineers spend days grepping by eye.

SpecImpact ingests these workbooks into an evidence graph (every claim links back to a cell range), then classifies impact candidates as must/should/may-review. The LLM only proposes; a verifier requires direct evidence before anything becomes "must review". Runs fully local; external LLM calls are opt-in per job.
