# v1.2.0 UX Phase 1 Review

## Implementation summary

Phase 1 replaces the production prototype and mock-data path with a compiled React/TypeScript
Evidence Review Workspace shell. FastAPI remains the localhost-only server and JSONL project API.

## Changed files

- Added the Vite frontend under `frontend/` with typed API access and six URL-addressable views.
- Replaced the large server template with a minimal application mount.
- Added compiled, locally packaged CSS and JavaScript assets.
- Added compatibility redirects for legacy GUI routes while preserving `project_id`.
- Removed old static scripts, embedded mock data, remote font use, and duplicate Cytoscape assets.
- Updated GUI tests and Japanese documentation.

## Verification

- `npm run check`: pass
- `npm run build`: pass
- `pytest -q`: 137 passed
- `ruff check .`: pass
- `python -m compileall -q specimpact`: pass
- `specimpact release-check ./examples/evaluation/release_cases.yml`: pass, 21 cases

Manual browser checks use a real guided-sample project. Dashboard counts, 13 impact candidates,
four highlighted source lines, Evidence Inspector content, a nonblank Cytoscape canvas, Alias empty
state, job records, settings, routing, and 390 px responsive layout were verified without console
errors. The mobile Inspector has an in-panel close action.
The wheel-install test also verifies that the compiled application, stylesheet, and React/graph
chunks are packaged.

## Known limitations

- Onboarding and Source Library are Phase 2 work.
- The complete three-pane review workflow and decision controls are Phase 3 and Phase 4 work.
- Dense graph-label management needs further Graph UX work.
- External approval still uses the existing service flow; the modal experience is refined later.

## Scope check

This phase changes the frontend foundation and routing only. It does not introduce the patent-sensitive
Impact Proof Twin algorithm, source-version semantics, or future review-state services.
