# v1.3.0 Agent Host Phase 2 Review

## Implementation Summary

SpecImpact now runs as an optional MCP 1.x stdio server. The server exposes domain-specific tools,
bounded resources, workflow prompts, and the same Pydantic JSON Schemas used by REST. Mutations use
a project process lock and hashed idempotency ledger. Long work returns durable local Job IDs.

External host authorization is represented by a ten-minute, project/purpose/source-bound, one-time
grant. Only metadata and token hashes are persisted.

## Changed Files Summary

- `specimpact/mcp_server.py`: stdio transport, tools, resources, prompts, and Job integration.
- `specimpact/application/{security,mutations,jobs,approval,resources}.py`: shared infrastructure.
- `specimpact/webui/{app,jobs}.py`: Application mutation path and compatibility import.
- `specimpact/cli.py`: `specimpact mcp --stdio --project` command.
- `tests/test_application_infrastructure.py`: boundary, lock, migration, and idempotency tests.
- `tests/test_mcp_server.py`: MCP schemas, resources, approval, pagination, and REST schema tests.

## Known Limitations

- MCP transport is stdio only.
- Host LLM sampling and prepare/submit workflows are intentionally deferred to Phase 3.
- Running jobs cannot be force-killed; only queued jobs can be cancelled.
- MCP Tasks are not advertised because the SDK's current Tasks API is deprecated and no longer in
  the core specification.
