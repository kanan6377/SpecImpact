# v1.2.0 UX Phase 5 Review

## Implementation summary

Phase 5 adds append-only source versions, transaction-linked graph diffs, and stale dependency
propagation without changing v1 collections or report schemas. `LocalStore.merge_graph()` captures
one before/after context, resets affected confirmed relations, and records stale evidence, nodes,
relations, and impact decisions.

## Changed files

- Added `SourceVersion`, `GraphDiffRecord`, and `StaleRecord` models and services.
- Integrated freshness capture with every graph merge path.
- Added stale annotations to graph nodes, graph edges, relations, and impact decisions.
- Added Source Library version/stale counts and Review Queue graph-diff decisions.
- Added `/api/projects/{project_id}/freshness`.
- Added model serialization, propagation, diff, resolution, API, and GUI projection tests.
- Updated README and Japanese manuals.

## Known limitations

- Version records track ingested content hashes, not a full copy of every source body.
- Evidence/node stale records remain as audit history after related review records are resolved.
- Cross-project and remote-backend transactions are outside the local JSONL default scope.

## Scope check

All new state is stored in v2 additive collections. The implementation does not auto-edit sources,
change v1 report output, expose confidence, or include patent-sensitive impact algorithms.
