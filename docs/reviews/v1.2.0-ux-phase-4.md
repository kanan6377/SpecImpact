# v1.2.0 UX Phase 4 Review

## Implementation summary

Phase 4 introduces one evidence-backed Review Queue for graph proposals, unresolved mentions,
aliases, relations, and impact decisions. The view provides domain-specific comparison details and
persists decisions only through existing project jobs and core services.

## Changed files

- Added the `/ui/reviews` route and `/api/projects/{project_id}/reviews` projection.
- Added graph node/edge diff preview before proposal decisions.
- Added alias context, relation properties, impact hypothesis details, and evidence quotes.
- Added confirm/reject/status controls for each supported review type.
- Redirected the legacy Alias page to the unified queue while preserving the Alias API.
- Added aggregation and persisted-decision regression tests.
- Updated README and Japanese manuals.

## Known limitations

- Unresolved mentions are displayed as `needs_investigation`; resolving them to a new graph target
  requires a later dedicated workflow.
- Review filters are URL-addressable but named saved views are not persisted yet.
- Source versions and stale decisions are Phase 5 work.

## Scope check

The API is a read-only projection over existing records. Mutations reuse `graph_proposal_decide`,
`alias_confirm`, `alias_reject_candidate`, `relation_status`, and `impact_status`. It does not add
confidence output, final automatic decisions, or patent-sensitive analysis logic.
