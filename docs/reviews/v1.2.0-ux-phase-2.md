# v1.2.0 UX Phase 2 Review

## Implementation summary

Phase 2 adds GUI-native project onboarding and a Design Sources workspace. A user can create or
register a local project, generate the guided sample, upload supported design sources, run the
existing ingestion actions through the project queue, and inspect a real Source Library summary.

## Changed files

- Added the `/ui/sources` route and legacy ingest redirects.
- Added a read-only `/api/projects/{project_id}/sources` summary assembled from existing JSONL data.
- Added project creation and guided-sample onboarding to the production frontend.
- Added managed upload for documents, Dirty Excel, OpenAPI, DDL, and CSV.
- Reused external-transmission preview, CSRF/session protection, project queue, and core consent.
- Added responsive Source Library and source-ingestion tests.
- Updated README and Japanese manuals.

## Known limitations

- Browsers cannot expose a native directory picker path to the server; onboarding accepts a local
  path and source addition uses managed file upload.
- Source version, stale evidence, and graph diff are intentionally deferred to Phase 5.
- Transactional proposal decisions are Phase 4 work.

## Scope check

This phase does not add a source-version model, stale propagation, auto-editing, or patent-sensitive
analysis logic. Source Library is a read-only projection of existing persisted collections.
